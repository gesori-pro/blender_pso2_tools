FLTD 33 자동 물리 미리보기 적용 기록 (2026-10-17)

사용
Blender를 새로 실행한다. PSO2 AQP 또는 ICE 불러오기에서 FLTD Cloth Physics가 기본으로 켜진다.
같은 모델의 AQP/AQN/FLTD가 함께 있어야 한다. Preserve NGS Weights도 켜고 Automatic Bone Orientation은 끈다.
지원되는 리소스는 치마와 넥타이의 시간 상태, 원본 제약, 본 재구성, 움직이는 충돌체를 자동 연결한다.
타임라인을 순차 재생하면 이전 프레임 상태를 이어서 계산한다. 원본 메쉬 좌표와 웨이트를 수정하지 않는다.
PSO2 Game Skinning 패널의 FLTD 물리 켜기/끄기와 현재 자세에서 물리 초기화로 제어한다.
초기 안정화 단계는 기본 30이다. 0~120 범위에서 바꿀 수 있다.

입력과 저장
AQN NODE의 low flag와 계층/TRS, inverse-bind, FLTD 원본을 사용한다. sa.aqm 적용 옵션도 존중한다.
파일의 boneShort2는 소켓/모션 메타데이터이므로 런타임 FK flag 상위 비트로 합치지 않는다.
기존 네이티브 체형/모션 프로필이 있으면 그대로 사용한다. 새 일반 AQP에는 파일 TRS 기반 프로필을 만든다.
Blender의 로컬 채널과 오브젝트 이동을 입력으로 사용하고 충돌체를 같은 프레임의 물리 전 FK에서 다시 만든다.
시간은 씬 FPS, 중력은 씬 Gravity를 사용한다. 풍력/환경 상대속도는 명시적으로 0이다.
되감기, 프레임 건너뛰기, FPS 또는 오브젝트 스케일 변경은 현재 자세에서 다시 초기화한다.
방문하지 않은 중간 프레임을 계산한 것으로 간주하지 않는다. 순차 프레임이 아닌 임의 프레임 렌더에는 캐시/베이크가 필요하다.
blend에는 원본 입력과 설정을 보관한다. 다시 열 때 원본에서 초기화하며 저장된 최종 포즈를 재생하지 않는다.
현재 위치에서 다시 안정화되므로 저장 직전의 전체 시뮬레이션 이력을 비트 단위로 이어가는 기능은 아니다.

지원 범위
V10 FLTD, solver 33, 자기 리소스의 정확한 본 이름, 동일 길이의 선형 체인만 지원한다.
파일 collider kind 1/5/7을 각각 런타임 sphere 0/plane 5/capsule 7로 처리한다.
본 이름 일부 일치나 근접 탐색을 사용하지 않는다. 미지원 콜백/변종/분기/다른 리소스 연결은 경고하고 자동 물리를 켜지 않는다.
기존 샘플의 치마 48개, 넥타이 3개 입자와 충돌체 5개/1개를 확인했다.

REA 근거와 한계
REA 6.5.0 / Ghidra 12.1.4로 기존 매핑/재구성/dispatch와 추가 생성자, 스케일 블렌드, collider 정렬을 확인했다.
28BF0A0 / 28C3490: 체인 매핑과 재구성 레코드.
28BBE60 / 28BFE30 / 28BF6B0: shape 생성과 정확한 이름 및 슬롯 연결.
B71910 / 28CCC10: 초기 플래그 및 identity 슬롯.
28CC880 / 28C24F0 / 28C27C0~28C2820: 파일 값과 블렌드/플래그 변환.
28F2920 / 28F8630: sphere/capsule prefix와 plane suffix 순서.
28C2880: transform 준비 -> solver -> 본 writeback.
수집 데이터는 검증에만 사용하며 자동 드라이버는 최종 본 행렬이나 입자 덤프를 읽지 않는다.
라이브의 실제 프레임 외력, LOD/환경 제어와 전체 FNP 기준 본 생성은 동적 1:1 검증 미완료다.
따라서 이 기능은 원본 파일에 기반한 물리 미리보기이며 실제 게임과 동작 1:1 완료판으로 표시하지 않는다.
성능은 Python 구현이며 게임과 같은 실시간 속도는 보장하지 않는다.
라이브 EXE/DLL/설치 리소스와 기존 샘플 blend는 수정하지 않았다.
