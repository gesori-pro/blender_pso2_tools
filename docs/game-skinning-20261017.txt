PSO2 Game Skinning / 게임 웨이트 미리보기
2026-10-17

구현 범위
1. 캡처 웨이트 재현: 실제 입력 정점, ushort4 웨이트, 팔레트와 최종 본 행렬로 스키닝한다.
2. 기준 AQN 실시간 비교: 편집한 바인드 골격은 유지하면서, 지정한 기준 AQN의 본 시작점을 사용하는 별도 리그를 만든다.
3. 정점별 계산: 슬롯 4개, 저장 웨이트와 실제 적용 웨이트, 팔레트 인덱스, 본 이름, 본 행렬과 위치 기여도를 보여준다.

현재 열린 Blender에 패널을 등록했고 설치 폴더에도 반영했다. 애드온 버전 번호는 변경하지 않았다.
N 패널 > PSO2 > Game Skinning / 게임 웨이트

캡처 비교
- '캡처 웨이트 미리보기 가져오기'에서 *.skinning.json 프로파일을 선택한다.
- 원본 치마와 겹쳐 보이면 Outliner에서 원본 치마 표시를 꺼서 비교한다.
- 생성된 치마를 선택하고 '게임', 'Blender', '기준 정점' 버튼을 누른다.
- '게임'은 캡처에 기록된 한 프레임의 결과다. 게임 물리를 계속 계산하는 모드는 아니다.
- 프로파일은 Text 데이터블록에도 포함되므로 blend만 다시 열어도 비교와 정점 분석이 가능하다.
- 정점 그룹에는 실제 GPU 적용 웨이트가 기록된다. 캡처 스냅샷에서 그룹을 칠하는 것으로 고정 캡처 좌표가 다시 계산되지는 않는다.

정점 분석
- 캡처 메시를 선택하고 '정점별 웨이트 계산 보기'를 누른다.
- Edit Mode에서 정점을 활성화한 상태면 그 정점 번호를 기본값으로 사용한다.
- Object Mode에서는 원하는 정점 번호를 입력한다. 앞 허리띠(EID 305)는 160이 조사한 문제 정점이다.
- 결과는 Text Editor의 'Skinning EID305 vertex160' 같은 이름에 저장된다.
- 좌표는 PSO2 모델 공간의 미터 단위다. game_minus_blender_mm는 밀리미터 단위다.
- GPU의 네 번째 웨이트는 저장된 w가 아니라 max(0,1-(x+y+z))다. xyz 합이 1 이상이면 네 번째 영향은 생략되며 재정규화하지 않는다.
- 본별 기여도 비교는 같은 GPU 웨이트를 게임/Blender 행렬에 각각 적용한 값이다. 원본 Blender 메시의 float 웨이트와 양자화된 GPU 웨이트 사이에는 작은 차이가 남을 수 있다.

기준 AQN 실시간 비교
- 원본 리그 또는 그 리그가 변형하는 메시를 Object Mode에서 선택한다.
- '기준 AQN으로 실시간 비교'에서 제작에 사용한 기준 AQN을 지정한다.
- 기본 본 필터는 hemroot,hem_,drs2_tube_skirt_ 이다. 비우면 매칭된 모든 본을 비교한다.
- 별도 컬렉션/리그/메시를 만들고 원본의 포즈 채널을 드라이버로 따라간다.
- 원본 바인드와 기준 AQN 사이의 부모 상대 시작점 차이만 보정한다. 전체 체인을 같은 거리로 움직인 경우 루트에서 한 번만 보정한다.
- Blender의 스케일 상속 규칙을 그대로 사용해 부모 스케일이 달라지면 위치 차이도 함께 달라진다.
- 복제 메시의 웨이트를 수정하면서 이 기준에서 변형을 확인할 수 있다. 원본 메시 데이터와는 독립적이다.
- 원본의 바인드/본 계층/메시 토폴로지를 다시 바꾸면 새 미리보기를 생성해야 한다.
- 이 도구는 시작점 차이 진단이다. 기준 AQN의 회전/스케일 변경이나 FLTD의 움직임을 일반적으로 복원하지 않는다.
- 제약이 있는 원본 리그/메시, 여러 Armature modifier가 있는 메시는 현재 거절한다.
- 이미 절대 위치 모션이 기준점 차이를 복원한 포즈에는 같은 기준 오프셋을 다시 더하지 말아야 한다.

검토 파일
별도로 전달한 skirt_game_skinning_preview.blend에는 게임 캡처 치마 3개와 원본,
기준 AQN 실시간 비교 컬렉션이 들어 있다. 기본 표시는 캡처 치마이며,
실시간 비교 컬렉션은 숨겨 뒀다. 원본 작업 blend에 저장하지 않았다.

검증
- 순수 계산 테스트 5개: 암묵적 네 번째 웨이트, 정규화 생략, 팔레트 간접 참조, 범위/NaN 검증, 프로파일 버전 검증.
- 실제 Blender 5.1.2에서 등록된 operator로 캡처 가져오기, 비교 전환, 정점 분석, 기준 AQN 비교 실행.
- 실제 RenderDoc post-VS 좌표를 역투영한 독립 기준과 비교해 최대 0.000320067mm 차이.
- hemroot 78.5290599mm 차이와 체인 시작점 12개의 단일 보정 확인.
- 부모 스케일 변경 시 보정량 연동 확인.
- 원본 본 rest/pose, 메시 정점/웨이트 fingerprint 불변 확인.
- 별도 blend를 저장하고 새 Blender로 다시 열어 드라이버 2,080개와 내장 프로파일 동작 확인.

소스
pso2_tools/skinning_math.py: bpy와 분리한 검증/계산/정점 기여도
pso2_tools/game_skinning.py: AQN 기준점 비교, Blender operator 및 패널
pso2_tools/__init__.py: 새 모듈 import 한 줄
순수 테스트: python -m unittest discover -s tests -p test_skinning_math.py
Blender 통합: tests/blender_game_skinning.py, tests/blender_skinning_readback.py

네이티브 분석 상태
pso2.exe, pso2reboot.dll, pso2bridge.dll 및 PhysX 관련 DLL 4개의
PE 정보/내보내기/의존성과 보존 해시를 확인했다. 게임 EXE/DLL의 포장된 코드 때문에
디스크 파일만으로 실제 본 갱신 함수까지 복원하지 못했고, 앞선 읽기 전용 프로세스 접근은 access denied였다.
PhysX 라이브러리가 있다는 사실만으로 FLTD가 그 API를 사용한다고 결론내리지 않았다.
따라서 전체 네이티브 엔진/물리 구현을 완료했다는 결과가 아니다.
게임 실행파일/DLL/ICE는 수정하지 않았다. 동작 근거는 캡처의 실제 GPU 버퍼와 명시적으로 지정한 기준 AQN이다.
