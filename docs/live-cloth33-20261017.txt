Live version 33 cloth port: development status, 2026-10-17

This is NOT a finished live garment solver. Normal character import does not
enable it. Full native_physics_implemented remains false. Existing source
meshes, AQP/AQN/FLTD, user blend files and client executables are unchanged.

Recovered code, translated to float32 Python (no copied client machine code
is loaded into Blender):
  native_physics_math.py: integrator 2907570
  native_cloth_stages.py: external force 28F3200, spring force 28B5A00,
    version-33 velocity drag 28F2CA0, pin/axis attachment 28F3640,
    target pull 28F3DC0, distance sections 29034A0/28FE440,
    circular cone leaf 28F5A50 (NOT its elliptical/mutable-state wrapper).
  native_cloth_writeback.py: reconstruction leaf 290AD30, record-order
    writeback 290A750. Preserve unmapped nodes and observed hemroot identity.
    Assembly confirms child translation W is forced to 1 at 290B59D;
    decompiler pseudocode omits this instruction's effect.
  native_cloth_solver33.py: stateful audited dispatcher subset with explicit
    rejection of angular/collider configurations and unknown mode bits.
  native_cloth_driver.py: explicit development driver with history. Duplicate
    frame evaluation restarts from the state BEFORE that frame; it does not
    integrate again. Rewind, skipped frames and FPS changes require explicit
    reset/replay. Initial state is explicit, not a copied final bone pose.
  native_float_estimates.py + dotnet/Pso2Tools.PhysicsMath: hardware SSE
    RCP/RSQRT provider. Exact division is not silently substituted.

Connection to Blender:
  native_pose_profile.evaluate_profile(..., cloth_step=...) calls the driver
    after recovered native FK, before model/axis transforms and inverse bind.
  live_skinning.set_cloth_driver(rig, driver) is a development API only.
    Normal import has no cloth driver and no extra animation mode.
    Temporal drivers are not serialized. A reopened file requiring a driver
    reports that it must be reattached. Existing cached vertex attributes can
    remain visible but are explicitly stale; no current-frame solve is claimed.
    The viewport continues through the existing raw NGS weight deformer.
