PSO2 라이브 버전 33 물리: Blender 이식 진행 결과 (2026-10-17, 2차)

현재 상태
제공받은 실제 제약과 충돌체를 읽어 버전 33의 관측된 계산 경로를
Blender 개발용 드라이버에 반영했다. 고정 최종 본 행렬을 복사하는 방식은 아니다.
초기 입자와 이전 상태를 받아, 입력 본과 충돌체의 움직임에 따라 매 단계
물리 계산 -> 본 재구성 -> 기존 raw-weight 메시 변형으로 진행한다.
일반 캐릭터 불러오기에 실제 라이브 물리를 자동 적용하는 완성판은 아니다.
라이브의 초기화와 프레임 입력 생성 경로, 실제 움직임과의 1:1 검증은 남았다.

받은 자료 검증
원본 live-solver-inputs-33-01에서 1,345개 파일 / 158,275,638바이트를
로컬 received에 복사했다. 원본 manifest 해시와 복사본 재읽기를 전수 검증했다.
누락 0. 수집본 안의 실행파일이나 스크립트는 실행하지 않았다.
독립적으로 비교한 코드 28개 범위는 기존 원본 .text와 바이트가 일치했다.
원본 수집은 비원자적이며, 화면 인스턴스나 최종 GPU 행렬로 확정하지 않는다.

이번에 추가한 복원
- 실제 거리 제약 106개, 각도 제약 24개, 타깃 각도 12개와 치마 입자 48개.
  넥타이는 입자 3개, 거리 2개, 각도 1개, 타깃 각도 1개.
- 각도 wrapper 28F70F0의 관측 모드. 2방향 한계의 내부/경계 계산과
  일반/타깃 제약 순서, 충돌 후 부모 고정 처리를 구현했다.
- 구형 tag 0 / 28CF110, 바닥 tag 5 / 28D9760,
  두 본을 사용하는 캡슐형 tag 7 / 28E4CD0의 관측 경로.
  실제 순서는 치마 [7,7,0,7,5], 넥타이 [7].
- 본별 축 크기, 양끝 반경, 각 스프링의 접촉 구간, 내부 포함 판정,
  고정 입자, 접촉 후 반사, 마찰과 sleep/exclusion 필터를 반영했다.
  일반 엔진의 질량 비례 충돌로 대체하지 않았다.
- 실제 스프링 레코드 +24/+28의 접촉 구간을 보존했다.
  패딩에 남은 상위 바이트를 제약 플래그로 해석하지 않는다.
- 전체 dispatcher 29048F0의 전/후 제약 반복, 접두 충돌체 처리,
  packed-normal 반사, 나머지 충돌 처리 순서를 연결했다.
- 매 프레임 충돌체 변환을 받는 provider와, dt/reciprocal_dt/외력/바람/
  상대속도/배율을 받는 별도 provider를 연결했다.
  실제 호출값이 없는 상태에서는 이 값들을 라이브 측정값으로 표시하지 않는다.
- 실제 자료의 파라미터 reader는 선택한 인스턴스와 accepted sample을
  명시적으로 받고 길이와 SHA-256을 검사한다. 최종 포즈나 위치 이력을
  자동으로 가져와 물리인 것처럼 보여주지 않는다.

독립 실행 검증
원본 .text의 해당 수학 함수를 게임과 분리된 Linux 프로세스에서 실행하고,
같은 float32 입력에 대한 Python 결과와 비트 단위로 비교했다.
Blender에는 원본 게임 기계어를 넣지 않았다. Blender에서는 복원한 수학 코드와
하드웨어 SSE RCP/RSQRT 보조 DLL을 사용한다.

- 각도 경로 4,096건 일치.
- 실제 제약 레코드의 전/후 각도/거리 조합 256건 일치.
- 포함 판정과 선분 접촉 primitive 6,144건 일치.
- 바닥 / 구형 / 캡슐형 각각 1,024건 일치.
- 실제 파라미터, 모든 충돌체를 연결한 192단계 일치.
- accepted 정지 묶음 6개에서 치마/넥타이 각 48단계,
  총 576단계의 이동/회전 충돌체와 가변 dt 시험 전부 일치.
  위치 4성분, 이전 위치, 외력 scratch, sleep mask를 비교했다.
  이때 움직임과 환경은 시험용 입력이며 라이브에서 수집한 움직임이 아니다.
- Blender 5.1.2 배경 프로세스의 합성 3본/삼각형 fixture 60프레임 통과.
  세 충돌체 종류, 각도 제약, 시간/환경 provider, 본 재구성,
  실제 평가된 Geometry Nodes 메시를 연결했다.
  메시와 입자 위치의 최대 성분 오차 5.960464477539063e-08 모델 단위.
  실제 의상 전체와 라이브 GPU 결과를 비교한 시험은 아니다.
- 계약/회귀 테스트 40개 통과. 중복 프레임은 추가 적분하지 않고,
  되감기/프레임 건너뛰기/FPS 변경은 reset 또는 replay를 요구한다.
  드라이버가 없는 재열기에서는 캐시가 오래된 상태라는 오류를 표시한다.

FLTD와 본 대응에서 확인한 사항
FLTD 파일 헤더 버전 10은 실행 중 solver 버전 33과 다른 값이다.
FLTD 선언은 왼쪽/오른쪽 허벅지 alt -> twist-alt, body_root, hip,
hemroot -> spine2, 넥타이 l_breast_scale -> r_breast_scale이다.
파일 kind와 실행 중 variant 번호 및 처리 순서는 동일하지 않다.
정지 상태에서 허벅지와 hip 등은 정확히 같은 행렬 후보를 찾았다.
다만 hemroot는 두 인스턴스의 대응 결과가 다르고, 넥타이 두 변환은
수집된 네 CPU 본 버퍼 안에서 완전히 같은 행렬을 찾지 못했다.
선언된 이름만 보고 최종 변환 생성 경로를 확정하거나 임의 보정하지 않았다.

설치와 보존
설치된 Blender 확장 폴더의 관련 소스 11개를 갱신하고 바이트 재검증했다.
기존 파일 백업은 installed-before에 보존했다. installation.json에 기록했다.
사용자가 실행 중인 Blender를 재시작/강제 reload하지 않았고 작업 blend를
열어 저장하지 않았다. 원본 AQP/AQN/FLTD/FNP, ICE, EXE/DLL도 바꾸지 않았다.
일반 import에는 드라이버가 자동 연결되지 않는다.
KernelClothDriver33 + live_skinning.set_cloth_driver는 개발용 API이다.
미확인 입력을 추정해서 자동 활성화하면 기존에 보인 잘못된 찌그러짐을
재현할 수 있어 완성된 라이브 1:1 기능으로 노출하지 않았다.

남은 목표
1. FLTD/AQN/체형/모션에서 실제 초기 입자와 rest 제약을 만드는 경로.
   수집 상태는 특정 실행 시점의 증거이며 모든 캐릭터의 초기화 규칙이 아니다.
2. 충돌체의 현재/역변환 생성 함수와 본 버퍼 선택, 특히 hemroot/넥타이 경로.
3. 실제 호출의 dt, stopping reciprocal, 외력, 바람, 상대속도와 exclusion mask.
   wrapper 29082C0에는 환경 조립과 배율 계산이 있으므로 상수로 대체하면 안 된다.
4. FNP/SA/AQM/대기 모션의 라이브 본 갱신을 동일 입력으로 연결하고,
   정지 및 회전/모션의 연속 결과를 실제 CPU 최종 배열과 비교할 것.
5. 그 결과를 실제 렌더/GPU 정점 출력과 대조할 것.
   기존 CPU215 포즈의 약 0.001498 basis 잔차도 해결 여부를 별도로 추적한다.
6. 관측되지 않은 basis propagation(0x2000), point/filter-list 모드,
   캡슐 growth/scratch 모드는 현재 명시적으로 미지원이다.
